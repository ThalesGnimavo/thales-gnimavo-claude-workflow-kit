## D1 — What the next roadmap starts with

**Decided :** a short "launch hygiene" slice first (D3, D4, D6, D7 below), then the first
outside run, logged step by step. Spanish docs, the Windows walkthrough and fleet without
iTerm2 stay in the backlog until the first outside feedback ranks them.

**Reason :** two defects surfaced without any outside reader (the empty `/fr/kit` landing,
no link from the author's own site). Leaving them for "what the first reader breaks" wastes
that reader. The user added: the outside reader can wait; no product with known bugs.

**The one guard the user's sentence needs :** "no bugs" is never reached; the `[0.1.0]`
"Untested at this release" list exists because of that. The written criterion for inviting
the first reader is: the hygiene slice shipped, **and** Proof due 7 (blank machine) observed.
Without a criterion, "not in a hurry" becomes "never".

**Way back :** reorder `phases_queued` in `casp/state.json`; the prompts are independent files.

**Way back :** skip `DISTRIBUTION-ARTICLE.md` and post the `/kit` page directly.

## D4 — Support: where a person stuck at step 3 of `INSTALL.md` writes

**Decided :** GitHub issues, one template ("where did you stop, what was printed"), named in
`INSTALL.md` and on the `/kit` page.

**Reason :** public and traceable; every answer helps the next reader. The contact form of
the blog is softer for a non-technical person but leaves no trail. Revisit if the first
non-technical readers do not open issues.

**Way back :** add the blog's contact as a second channel in `INSTALL.md`.

## D5 — Release cadence

**Way back :** a per-defect release is one tag more; nothing structural.

## D6 — The `/kit` page in three languages (user's item)

**Decided :** one component, strings through the site's i18n keys, three routes `/kit`,
`/fr/kit`, `/es/kit`; the homepage button and the product card follow the language. The
Spanish page says the kit's manual exists in English and French today.

**Reason :** the kit targets non-developers first, and the author's French-speaking public
is the first concerned; an English landing from `/fr` contradicts the promise of the page.
Not chosen: English only with `/fr/kit` redirecting to `/kit` (one line, same contradiction).

**Where :** the website repository (`ThalesAndHisAiCtoClaude.com`), its own rules (no
inline build without the user's approval, `/verify-thales` after the push). Listed in
`LAUNCH-HYGIENE.md` as companion work with the repository path.

**Way back :** delete the two language routes; the English page stays.

## D7 — The link on justegnimavo.com (user's item)

**Decided :** two placements, two targets. In the "Featured writing" block, a second button
"Claude Workflow Kit — free" to the blog's `/kit` page with a utm parameter. In the "Open

**Reason :** the page explains and is measured; the repository speaks to developers; each

**Where :** the `justegnimavo-com` repository (static HTML, `index.html`). Listed in

**Way back :** remove the button; the repository row can stay.

## D8 — Short links `/go/kit` and `/go/kit-zip` (user's item, raised after the close of the first pass)

**Decided :** two entries in the website's `TRACKED_ASSETS` allowlist
(`src/lib/server/tracked-assets.ts`), the mechanism already used by `/go/workflow-guide`:

| Slug | Target | Use |
|---|---|---|
| `/go/kit` | `https://thalesandhisaictoclaude.com/kit` | the link given to anyone, WhatsApp included |
| `/go/kit-zip` | `https://github.com/ThalesGnimavo/thales-gnimavo-claude-workflow-kit/releases/latest/download/claude-workflow-kit.zip` | someone already briefed who wants the file |

Every release uploads the asset under that fixed name (`gh release upload vX.Y.Z
claude-workflow-kit.zip`), so the short link never needs editing; the release checklist in
`CHANGELOG.md` or `README.md` carries that line.

**Reason :** the user proposed `/go/claude-workflow-kit` to the repository and
`/go/download-claude-workflow-kit` to `archive/refs/heads/main.zip`. Three corrections
accepted: (1) never the `main` branch zip, which hands out an unversioned tree and makes any
issue unreproducible, against D5; (2) the WhatsApp link goes to the page, not the repository,
same reason as D7 (the recipient is rarely a developer; the page has the GitHub button);
(3) shorter slugs, because a WhatsApp link is dictated and retyped. The `main.zip` alternative
and the tag zip with a per-release slug edit were considered and declined (a link that rots
the first time the edit is forgotten).

**Caveat recorded :** both slugs land in the same events table as the PDF downloads; `kit`
counts visits, `kit-zip` counts files. The slug column tells them apart.

**Way back :** remove the two lines from the allowlist; `/go/<unknown>` already falls back to `/`.
